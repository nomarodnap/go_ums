# ระบบรายงานค่าสาธารณูปโภค กรมประมง (UMS v2)

ระบบรายงานและติดตามการเบิกจ่ายค่าสาธารณูปโภค กรมประมง พัฒนาด้วยสถาปัตยกรรม Decoupled Full-Stack ประสิทธิภาพสูง:

**Next.js 16 (App Router) + TypeScript + Zustand + TanStack Query v5 + Orval + GoLang + Chi + Huma v2 + PostgreSQL + sqlc + Goose + Redis + Asynq**

---

## จุดเด่นของสถาปัตยกรรม (Architecture Highlights)

1. **Go Backend (Chi + Huma v2):**
   - Routing รวดเร็วด้วย `go-chi/chi/v5`
   - Type-safe REST API และสร้าง OpenAPI 3.1 Spec (`/openapi.json`) อัตโนมัติด้วย `huma/v2`
   - Interactive API Documentation ที่ `http://localhost:8080/docs`
   - ระบบ JWT Authentication พร้อม RBAC Middleware สำหรับตรวจสอบสิทธิ์ 6 บทบาท
2. **Database & Cache Layer (PostgreSQL + sqlc + Goose + Redis):**
   - เขียนคำสั่ง SQL ล้วน คอมไพล์เป็น Type-safe Go ด้วย `sqlc` ผ่าน `pgx/v5` Connection Pool
   - บริหารจัดการ Database Migrations ด้วย `goose`
   - Cache ประสิทธิภาพสูงและ Message Broker ด้วย `redis:7-alpine`
3. **Background Job Queue (Asynq):**
   - จัดคิวงานเบื้องหลังแบบ Distributed ด้วย `hibiken/asynq` บน Redis (เช่น ส่งอีเมลแจ้งเตือน/ตั้งรหัสผ่าน) พร้อมระบบ Auto-retry และคิว Priority
4. **OpenAPI Client Generation (Orval):**
   - ดึง OpenAPI 3.1 Contract จาก Go Backend มาแปลงเป็น TypeScript Types และ TanStack Query Hooks โดยอัตโนมัติ
   - End-to-End Type Safety ข้ามภาษาระหว่าง Go และ TypeScript
5. **Next.js 16 Frontend:**
   - ใช้ React 19 และ Next.js 16 App Router
   - จัดการ Server State Caching และ Optimistic Updates ด้วย `TanStack Query v5`
   - จัดการ Client State และ User Preferences ด้วย `Zustand` (พร้อม Persistence middleware)
   - ตกแต่งด้วย Tailwind CSS v4, shadcn/ui สไตล์ Apple Canvas คุมโทนสะอาดตา พร้อม Lenis Smooth Scrolling และ Framer Motion
   - รองรับปีพุทธศักราช (พ.ศ.) และภาษาไทยสำหรับงานราชการ

## คำสั่งควบคุมระบบผ่าน Taskfile (แนะนำ)

โปรเจกต์นี้รองรับ [Taskfile](https://taskfile.dev/) เพื่อความสะดวกรวดเร็ว:

| คำสั่ง | คำอธิบาย |
| :--- | :--- |
| `task` | ดูคำสั่งทั้งหมดที่พร้อมใช้งาน |
| `task dev` | รันทั้ง Backend (8080) และ Frontend (3000) พร้อมกัน |
| `task dev:backend` | รันเฉพาะ Go Backend Server |
| `task dev:worker` | รันเฉพาะ Asynq Background Worker แบบ Standalone |
| `task dev:frontend` | รันเฉพาะ Next.js Frontend |
| `task gen` | รัน Code Generator ทั้งหมด (`sqlc` + `orval`) |
| `task migrate:status` | ตรวจสอบสถานะ Database Migrations (Goose) |
| `task migrate:up` | รัน Migration ทั้งหมดเข้าฐานข้อมูล (Goose Up) |
| `task migrate:down` | ย้อนกลับ Migration 1 ขั้น (Goose Down) |
| `task migrate:create -- <name>` | สร้างไฟล์ migration ใหม่ |
| `task redis:ping` | ทดสอบการเชื่อมต่อกับ Redis Server (192.168.171.97:6379) |
| `task redis:cli` | เข้าใช้งาน redis-cli กับ Redis Server ภายนอก |
| `task build` | คอมไพล์โปรเจกต์ทั้ง Backend, Worker และ Frontend |
| `task build:worker` | คอมไพล์เฉพาะ Asynq Worker ไบนารี (`bin/worker.exe`) |
| `task docker:up` | รันระบบทั้งหมดด้วย Docker Compose |
| `task docker:down` | ปิดระบบ Docker Compose |

## วิธีการรันระบบเพื่อการพัฒนาแบบดั้งเดิม (Manual Workflow)

### 1. รัน Go Backend (พอร์ต 8080)
```bash
cd backend

# คอมไพล์และรันเซิร์ฟเวอร์
go run cmd/server/main.go
```
- API Base URL: `http://localhost:8080`
- OpenAPI Specification: `http://localhost:8080/openapi.json`
- Interactive API Docs: `http://localhost:8080/docs`

### 2. อัปเดต Type & React Query Hooks เมื่อ Backend มีการเปลี่ยนแปลง
```bash
cd frontend

# สร้าง Hooks และ Models ใหม่จาก Go Huma OpenAPI อัตโนมัติ
pnpm generate:api
```

### 3. รัน Next.js Frontend (พอร์ต 3000)
```bash
cd frontend
pnpm dev
```
เปิดเบราว์เซอร์ที่ `http://localhost:3000`

## รันด้วย Docker Compose (Full Stack)
```bash
docker-compose up --build -d
```
คำสั่งนี้จะเริ่มต้นบริการ:
- PostgreSQL (พอร์ต 5432 พร้อม auto-migrate schema.sql)
- Go Backend API (พอร์ต 8080)
- Next.js Web Frontend (พอร์ต 3000)
